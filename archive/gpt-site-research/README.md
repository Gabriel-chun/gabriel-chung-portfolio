# GPT Site / AI-assisted Prototyping Archive

> Status: historical research archive, not the current portfolio.

This folder preserves an early phase of product exploration in which conversations with GPT were repeatedly turned into working interfaces, data structures, and review workflows.

## Why this archive exists

These projects were not a set of unrelated websites. They were a sequence of product investigations around one recurring question:

**How can messy human input become structured, reviewable, traceable work without losing the reasoning that produced it?**

The working pattern was usually:

```text
natural language / conversation
        ↓
frame a problem with GPT
        ↓
turn the hypothesis into a web prototype
        ↓
use the prototype with real material
        ↓
notice friction, ambiguity, or missing states
        ↓
change the information model / workflow
        ↓
build the next iteration
```

The value of these artifacts is not that every prototype should remain an active product. Their value is that they preserve the evolution of the research questions.

## Source bundle reviewed for this archive

### 1. Capture / Craft / Publish (IdeaFlow)

Source: `capture-craft-publish final.zip`

A Base44 prototype for turning raw thoughts into trackable material and possible outputs.

Observed elements include:

- raw thought capture;
- status progression: Raw thought → Clustered → Outline ready → Drafting → Editing → Ready to publish → Published;
- context area, item type, output type and tags;
- next action and related ideas;
- Today Focus / recent items / bottleneck view;
- constellation-style related-item view;
- output composer.

This prototype explored the transition from **capture → organization → possible output**.

### 2. Transcript / Thought Flow research

Source: `ChengChunHung_AI-Assisted_Transcript_Portfolio.pdf`

The portfolio documents a human-reviewed workflow for long-form spoken Chinese:

```text
Raw Transcript
→ Segmentation
→ Ambiguity Detection
→ Meaning Verification
→ Reasoning / Decision Path
→ Structured Review Output
```

The central design concern was to preserve reasoning order, context, ambiguity and hesitation before compressing the material into a clean summary.

Related historical GPT Site work includes Thought Flow Profile 07 / Transcript Lab / Inside Ideation Loop.

### 3. Inside Decision OS

Source: `Inside-Decision-OS-source-v147(1).zip`

Inside Decision OS expanded the earlier capture experiments into a more explicit work ontology.

Important concepts in the source include:

- Capture
- Draft Version / Draft Item
- Review Group / Review Plan
- Duplicate Candidate
- Formal Record / Formal Record Reuse / Merge
- Case
- Thread / Thread Membership / Thread Merge
- Decision
- Output / Output Proposal
- Dispatch
- Status History
- Daily Archive / Workspace Snapshot

A central principle is that AI-generated candidates are **not** treated as confirmed facts or decisions. Formal records require explicit user confirmation, and source / status history remain traceable.

This was the broadest attempt to model the path from raw natural language to continuing work and deliverables.

### 4. Shadowverse Prep Lab

Source: `shadowverse-prep-lab-source-v83.zip`

A domain-specific research environment applying the same structural ideas to competitive card-game preparation.

The source contains working surfaces for:

- environment research;
- decks;
- matchups;
- ladder / practice records;
- daily practice slices;
- quick capture / canvas;
- project lifecycle;
- Notion export / daily JSON backup;
- evidence-heavy reading hierarchy.

This prototype matters because it moved the workflow out of generic knowledge management and into a real decision environment with repeated practice, changing evidence and uncertain judgment.

## What changed later

Later work began to separate previously combined responsibilities:

- **Research Thread** — research context, frame, evidence, open questions and notes
- **Semantic Weave** — sequence, context, semantic relations and provenance
- **Global Project Overview / Control Room** — continuity across projects and a meta-level view of current work
- **Portfolio** — external communication of the parts mature enough to show

This archive should be used as evidence of design evolution, not as a claim that all historical prototypes are still active.

## Archive rule

When material from this folder is reused in the public portfolio:

1. preserve the original problem and constraint;
2. distinguish implemented behavior from later interpretation;
3. do not treat prototype status, version number, or deployment as proof of impact;
4. show what the prototype helped clarify;
5. explain what was kept, changed, merged, or retired.
