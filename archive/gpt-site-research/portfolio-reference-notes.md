# Portfolio Reference Notes — GPT Site Research

> Draft reference material. These are candidate portfolio angles, not final claims.

## Strong portfolio-level framing

### Rapid prototyping as research
I used conversations with GPT to turn unclear problems into testable web interfaces.

The prototypes were not treated as final answers. Each one made a hypothesis concrete enough to use, inspect and revise.

### Designing before automation
A recurring design choice was to preserve ambiguity and require human confirmation before converting AI interpretation into formal data or decisions.

### From language to traceable work
The project family repeatedly explored:

```text
messy language
→ meaningful units
→ ambiguity / verification
→ research or decision structure
→ continuing work
→ output
```

### Information architecture under uncertainty
The work is less about building a generic “second brain” and more about designing structures for:
- incomplete reasoning
- changing context
- provenance
- uncertain relations
- versioned states
- explicit human review

### Domain transfer
The same questions were tested across:
- spoken-language / transcript review
- idea and content development
- personal work continuity
- competitive card-game preparation
- cross-project overview

## Potential case-study questions

### AI-Assisted Transcript Structuring
**How can long-form spoken language become reviewable data without erasing the reasoning path?**

Evidence:
- explicit six-stage human-reviewed workflow
- ambiguity detection before rewriting
- source-to-review traceability
- structured entries with confidence and review status

### Inside Decision OS
**How should AI-assisted interpretation become continuing work without silently becoming truth?**

Evidence:
- explicit ontology
- separation of model candidates from formal records
- user-confirmed Decision
- provenance / status history
- Case vs Thread distinction
- snapshot / projection semantics

### Capture / Craft / Publish
**How little structure can an interface require at capture time while still helping material move toward output?**

Evidence:
- raw-thought-first capture
- possible output lifecycle
- Today Focus / bottleneck / related-item views
- lightweight classification / inference

### Shadowverse Prep Lab
**How can a research system support repeated judgment when the environment and evidence keep changing?**

Evidence:
- environment + deck + matchup + practice records
- daily logs
- Notion export / backup
- evidence-dense reading hierarchy

## What should probably NOT be claimed yet

Avoid presenting the archive as evidence that:
- the tools achieved product-market fit;
- the workflow was validated across many users;
- deployment or version count proves product quality;
- AI inference was always correct;
- every historical site remains an active standalone product.

The stronger story is:

**Each prototype exposed a new design constraint, and the later system architecture reflects what survived those experiments.**
