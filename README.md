## 為什麼保留 V1  
## Why Keep V1

第一版作品集記錄了我當時對自己工作的早期理解：**為混亂、未整理的人類思考設計可被理解與使用的系統。**  
The first portfolio captured an early framing of my work: **designing systems that make messy, unstructured human thinking understandable and usable.**

當時的案例已經開始處理：  
Its early cases already explored:

- 自然語言與想法整理工作流  
  natural-language / ideation workflows
- 卡牌遊戲中的推理、判斷與複盤  
  card-game reasoning and review
- 從研究走向產品與輸出的工作流程  
  research-to-product workflows

後來的 Control Room、Global Project Overview、Research Thread、Semantic Weave，以及各種領域型研究工具，很多都可以追溯到這一版作品集裡已經出現的問題。  
Later projects — including Control Room, Global Project Overview, Research Thread, Semantic Weave, and domain-specific research tools — grew from questions already visible in this first version.

## 重構原則  
## Rebuild Principles

新版作品集不會只是「我做過哪些網站」的畫廊。  
The new portfolio should not become a gallery of every website I made.

每一個重要案例更希望回答：  
Each selected case should instead show:

1. 我當時正在研究什麼問題？  
   What problem was I investigating?
2. 我做了什麼 prototype，讓問題可以被實際測試？  
   What prototype made the problem testable?
3. 實際使用後出現了什麼證據、摩擦或限制？  
   What evidence, friction, or limitation appeared?
4. 下一次迭代改變了什麼？  
   What changed in the next iteration?
5. 哪些想法最後被保留下來，進入後續系統？  
   Which ideas survived into later systems?

### 接下來怎麼追蹤
### Proposed Tracking Method

1. **先補 GPT Sites 的時間線。** GPT 逐站查詢可取得的版本紀錄，以版本時間、版本 ID、原始碼或差異記錄實際變更；無法取得的對話或歷史版本標記為待提供。
   **Reconstruct the GPT Sites timeline.** GPT reviews available version records per Site, grounding changes in timestamps, version IDs, source, or diffs. Unavailable conversations or historical versions remain marked as missing.
2. **平行補上 GPT Sites 以外的研究。** Claude 閱讀相關 GitHub repositories 的 README、commit 與現有研究檔案，整理其他工具與系統的發展；本節是交接提案，不代表 Claude 已讀取或完成分析。
   **Add research outside GPT Sites in parallel.** Claude reviews relevant repositories' READMEs, commits, and research files to document other tools and systems. This is a handoff proposal, not a claim that Claude has already reviewed or completed the work.
3. **用一致欄位描述工作。** 每筆記錄包含：日期／期間、專案、當時問題、實際修改、測試或使用觀察、保留或改變的想法、證據位置、已確認／推測／待查、整理者與查核日。
   **Use shared record fields.** Record date or period, project, original question, implemented change, test or use observation, ideas retained or changed, evidence location, confirmed/inferred/open status, reviewer, and verification date.
4. **比對後再建立研究脈絡。** 將 GPT Sites 與其他 repositories 的證據放在同一時間線，標記可能的承接關係與反例；不能以名稱、日期接近或版本數直接推出因果。
   **Compare evidence before establishing lineage.** Align Sites and repository evidence on a shared timeline, marking possible relationships and counterexamples. Names, adjacent dates, and version numbers alone cannot establish causation.
5. **再選作品集案例。** 優先呈現「問題 → 原型 → 使用證據 → 調整 → 後續保留」，細節逐步補入 `archive/gpt-site-research/`，根目錄 README 保留總覽與入口。
   **Then select portfolio cases.** Prioritize question → prototype → use evidence → revision → later reuse. Add detailed findings under `archive/gpt-site-research/`, keeping the root README as the overview and entry point.
